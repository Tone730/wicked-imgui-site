Code signing policy

Last reviewed: 18 November 2026 · Wicked Imgui, operated by an individual developer in Florida, United States.

Current status: the published v2.2.1 portable ZIP is not Authenticode-signed. Its integrity is published as SHA-256 and SHA-512 and checked by the updater. Windows may warn until a certificate is configured. This policy describes the process that will apply once signing is enabled; it is not a claim that current builds are signed.

1. Who may sign

Only the project operator (the individual developer identified in the Terms) may request, access or use a code-signing certificate or private key. No other maintainer, contractor or automated third party receives signing credentials. Build automation may call the signing script but must read credentials from its own secret store, never from repository files.

2. What gets signed

Only official Wicked Imgui release artifacts built from reviewed source are eligible: the Windows executable and, when an installer is produced, its installer binary. Development builds, test builds and third-party binaries are not signed with the release certificate. Each signed artifact is SHA-256 hashed and timestamped with an RFC3161 timestamp so validity survives certificate expiry.

3. Key custody

Private keys are stored in the Windows certificate store or a password-protected PFX in a location outside the source tree. Keys are never committed, attached to a release, pasted into a support ticket or sent by email. A lost or suspected-compromised key is revoked with the certificate authority and replaced before the next release.

4. Release procedure

Build and validate the app, sign the binary, then package and hash the final artifact. Publish the checksums in the release manifest and release notes. Re-run the updater tests after packaging. If any file changes after signing — including repackaging — the artifact is re-signed and re-hashed; old checksums are never reused.

5. Reporting a suspicious build

If you downloaded a Wicked Imgui build that does not match the published checksum, or a file claims to be signed by this project unexpectedly, email wick777@engineer.com with the file hash and where you got it. Include "Suspicious build" in the subject. Security notices go to leakz15@programmer.net.

6. Updates to this policy

Changes are published on this page with a new review date. Material changes to signing practice are announced in the changelog. This draft has not yet been reviewed by counsel; see LEGAL-REVIEW.md in the project for the review checklist.
